# 案例：E09M06B1 挤压生产原始记录 —— 子表打印不出来（2026-09-24）

> 承接 `mem:cloud-print.md` 第 5 条「坑④」。本文件是那次排查的完整对照记录，用于回答：
> **为什么最后那版模板能让三张子表都出数，之前的都不行。**
>
> 环境：k1038 OEM。页面 E09M06B1，模板 `E09E09M06B1Edit-挤压生产原始记录.grf`，
> 后端 `inks-service-oem-k1038` 的 `ExtrusionRawRecordController.printWebBill`（多子表报文）。

---

## 1. 结论

**只有最后一个版本满足「每个 XML 表名在模板里只出现一次」，其余版本都因为表名重复，导致部分或全部子表空白。**

报文的节点顺序、节点名、层数、数据，从头到尾都是对的——整个问题在模板侧。

## 2. 各版本对照

报文侧始终是：

```json
{"xml":{"Item":[{...}],"craft":[{...}],"bartemp":[{...}],"Master":{...}}}
```

三张子表在库里各有数据（已查 `inksk1038oem` 的 `Bus_ExtrusionRawRecordItem` / `Craft` / `BarTemp` 确认），后端也能取到。

模板侧各版本：

| 模板版本 | 主报表明细网格 | SubReport1 炉次号 | SubReport2 模具温度 | SubReport3 棒温 | 重复的表名 | 打印结果 |
|---|---|---|---|---|---|---|
| 最初导出件 | 无 | Report级 `Item` **+** 记录集级 `Item` | 只有 Report级 `craft` | 只有 Report级 `bartemp` | `Item`×2 | 三个子表**全空** |
| 变体A：给子报表补 `ConnectionString:"XML"` | 无 | 同上 | 同上 | 同上 | `Item`×2 | 未实测（结构上判断无效） |
| 变体B：删掉子报表 Report 级表名 | `craft`（验证用） | 记录集级 `Item` | 记录集级 `craft` | 记录集级 `bartemp` | `craft`×2 | 炉次号、棒温出数；**模具温度整表不显示** |
| `- 副本.grf` | `craft` | 记录集级 `Item` | **Report级 `craft`**（记录集级没写） | 记录集级 `bartemp` | `craft`×2 | 模具温度整表不显示 |
| `- 副本 - 副本.grf` ✅ | **无** | 记录集级 `Item` | 记录集级 `craft` | 记录集级 `bartemp` | 无 | 三张子表**全部正常** |

## 3. 逐版本解释

### 3.1 最初导出件 —— 三张全空，两个毛病叠加

- **SubReport1**：`Item` 填在了两处——子报表对象的「报表主对象 → xml 表名」（内嵌 Report 的 Report 级），以及子报表自己的记录集（`DetailGrid.Recordset.XmlTableName`）。锐浪先匹配给前者，名字被消耗，子报表明细网格再要就没了 → **列标题在，行数为 0**。
- **SubReport2 / SubReport3**：只在 Report 级写了表名，**记录集级根本没写** → 记录集没有绑定任何 XML 节点 → 同样空。

两张表的空法看着一样，成因其实不同。

### 3.2 变体A —— 没用

给子报表记录集补 `ConnectionString:"XML"` 是"声明数据源"，但病根是**表名重复**，不是数据源没声明。方向错了，没实测就转到 B 了。

### 3.3 变体B —— 解决两张，剩一张

删掉三个子报表的 Report 级表名后：

- SubReport1 / SubReport3：表名只剩记录集级一处 → **出数** ✓
- SubReport2：`craft` 又被**主报表那个验证用的明细网格**占着（设计时把它绑成了 `craft`），仍然是"表名出现两次"，主网格在模板里靠前、先匹配走 → **整张表连列标题都不显示** ✗

> 关键点：这个坑不只在子报表内部。**主报表明细网格和子报表撞名同样中招**，而且症状更重——连列标题都没有。

### 3.4 `- 副本.grf` —— 没解决

这一版里主报表明细网格仍是 `craft`，而 SubReport2 又退回成只有 Report 级 `craft`（记录集级仍缺）。`craft` 出现两次、且 SubReport2 自己没绑记录集 → 模具温度照旧不显示。

### 3.5 `- 副本 - 副本.grf` ✅ —— 全通

相对变体B只多做了一件事：**把主报表那个验证用的明细网格整个删掉**。此时：

- 主报表顶层键 = `Version / Font / Printer / Parameter / ReportHeader / ReportFooter`（**没有 `DetailGrid`**）
- 三个子报表都只有 `DetailGrid.Recordset.XmlTableName`，分别是 `Item` / `craft` / `bartemp`
- 三个表名各出现 **1 次**

三张子表全部正常。

这个形态和标准版能出数的多子表模板完全一致：`0226- grfpool/release/D05/D05M11/D05M11B1Edit-通用.grf` ——
它的子报表同样**只在记录集级写表名**，外层报表也没有明细网格。

## 4. 最终模板应有的形态

| 位置 | 应有内容 |
|---|---|
| 主报表 | `Parameter` + `ReportHeader` + `ReportFooter`；**不要**明细网格（表头值走 `Master` 节点，不需要明细网格） |
| 每个子报表 | 内嵌 Report **不写** Report 级 `XmlTableName`；只在 `DetailGrid.Recordset.XmlTableName` 写一次 |
| 子报表控件 | 放在 `ReportHeader` 的独立分段里即可，位置不是问题 |

对照当前的报文节点名：`Item` / `craft` / `bartemp`。

## 5. 本次被排除的怀疑点（省得下次再怀疑一遍）

| 怀疑点 | 结论 | 依据 |
|---|---|---|
| 后端报文结构不对 | 排除 | 打印日志里的报文节点、层数、数据都对 |
| 后端取子表没取到 | 排除 | 查库三张子表各有数据，`getEntity` 也返回了 |
| 打印工具 / 锐浪解析不了这种报文 | 排除 | 主报表明细网格绑 `Item` 能正常出数（对照实验） |
| 子报表缺 `ConnectionString:'XML'` | 排除 | 变体A 方向，实测前已由变体B 解决 |
| 两个对照模板不可靠 | 部分排除 | `D05M11B1` 绑的 `obj` 全后端无产出；`D07M02B1` 绑的 `Cash` 在财务模块后端也无产出。它们只能作**结构**参考，不能作"已跑通"的证据 |
| **模板里 XML 表名重复** | **真因** | 见第 2、3 节 |

## 6. 遗留待验证

模板里 SubReport1 写的是 `Item`（大写 I），而后端源码发的是 `item`（小写），实测**能出数**——怀疑锐浪的表名匹配不区分大小写。这与 `cloud-print.md` 第 1 条「必须完全一致且大小写敏感」的表述有出入，但只在一个方向验证过一次，**下次碰到时先实测确认再改文档**。稳妥做法仍是模板和后端写成一样。
